## Action-related benchmark root cause and evaluator contract

The current evaluator has no independent expected-action, expected-guardrail, or expected-approval labels in the frozen 500-case dataset. `ActionEvaluator._expected_action_type` maps `GroundTruth.expected_decision` (`AUTO_APPROVE`/`REVIEW`/`ESCALATE`) to an action type. This explains why all 189 action-type mismatches coincide with the 189 decision-outcome mismatches: the action-type target is a derivative of the same decision label. `_expected_guardrail_decision` then derives the guardrail target from that mapped action and the pipeline's risk assessment; `_expected_requires_approval` derives approval need from mapped action and that same predicted risk. Consequently, 210 guardrail mismatches and 308 approval mismatches are rule-consistency diagnostics, not independently adjudicated policy-quality measurements. They cannot establish the correct financial action policy.

The 252 unsuccessful action attempts are distinct from action-type mismatches and need provider-/executor-specific failure attribution. The available per-case benchmark records only a success boolean and error categories, not a downstream ERP response or human-adjudicated action. Therefore the benchmark cannot localize these failures to a reliable external execution cause. Across overlapping action-type, execution, guardrail, and approval categories, 498/500 cases have at least one recorded action-related error. Do not change action mappings or mocks to improve this synthetic score. Close this evaluator-contract gap by adding independently authored expected action/guardrail/approval labels, provenance, source invoice/job references, policy-owner sign-off, and predeclared acceptance gates, then rerun a frozen human-reviewed set.
